What you see

You start a new game. The log says "This game uses seed N." The header shows the day, then 1x held, then 2x, 4x, and Skip, then Pause and Restart. Day 1 wind is a number on the header.

The first article's short matches that seed. The number is Structure 60, Fuel lines at 0 seconds, or thrust 1400 kN. The sheet shows it after a test reads that part. The other two parts start healthy. An untested part still reads "not tested".

You press 4x. A build day takes 1 second. The road, the fill, the fire, and the flight keep their own clocks. Pause still stops the day and those clocks. You reload. The header still shows 4x.

On a closed day, with no job running, you press Skip. The day lands on the next open day. The header shows that wind. The lamp is open. On an open day, with nothing waiting, Skip does not move the day. The log says "Nothing to skip to."

A fill, a lit fire, or a flight makes Skip refuse. The day stays. The log names the tanks, the fire, or the flight. Escape during a fire still finishes the fire picture. Header Skip does not.

You reload an idle yard. The seed, the day, the wind, and the speed are still there. A 0.14.1 file with version 1 and seed: null continues. The sky stays the old table. The next article still follows Structure, then Fuel lines, then thrust. Restart asks, then rolls a new seed.

The rocket name stays Test article. Serials stay TA-1, TA-2, and so on. Steel stays 28. Build days stay 8 to 12. The bay prices stay. The wind number stays on the header after a Skip. The seed does not hide Structure or thrust, and it does not add a percent.

Two wiki sentences still name one fixed order. Both change in this same index.html pass. wikiLaunch at line 3000 is "How a test works." wikiTime is not that page. The Starfactory sentence is line 3238. Leave the order out of both. Keep the shorts 60, 0 seconds, and 1400 kN. Keep the restored-part rule. A restored part does not take the next short. The Numbers page at line 3148 names the three values and does not name an order. Leave that page alone.

The seed

G gains seed and speed on the state object at line 1023. The object starts with seed: null and speed: 1. A null or missing seed is not a roll. undefined >>> 0 is 0, so a missing seed must not fall through into roll.

weatherOn and the defect picker call roll only when the seed is a whole number from 0 through 4294967295. Anything else uses the old order and the old sky. 0 is a valid seed. Only null means this file has no seed.

The roll uses crypto.getRandomValues into one 32-bit value. If that call throws, the fallback is Math.floor(Math.random() * 4294967296). Both can return 0.

The game does not write the save on that roll. The first dayTick autosave is still the end of the day. An idle reload on day 1 is the pagehide write at line 5585. That write runs when no fill, fire, or flight is running, and it keeps the seed. A new roll happens only when no file was written. "Day 1 has no save yet" means only that dayTick has not written.

On the normal page, Restart still opens the card. The words stay "Start a new game? The current yard is lost." Cancel leaves the save and the seed. Start over runs restartGame at line 5529. That drops starbase-save and reloads. The new page finds no file and rolls a new seed. The log line is "This game uses seed N." A continued file does not print that line again.

The test page does not open that card. The click at lines 5581 to 5583 calls restartGame at once. restartGame drops the key only when TEST is false, at line 5531. A test restart reloads, uses seed 11 again, and does not delete starbase-save.

ROCKET_DEFS.article at line 931 stays name "Test article", short "TA", steel 28. finishFactoryJob at line 1545 still names the serial from the living fleet count. This row does not tie that serial to builtArticles.

Boot order

The boot sets the seed before renderChrome at line 5746. That paint calls weatherOn. A seed that is still null at that paint shows the old sky. Day 1 of seed 11 is also Clear 8 kn, so that paint hides a missed seed.

  1. G already holds seed: null and speed: 1.
  2. If the URL has test, set the seed to 11. Do not read starbase-save. Do not roll. The next step is the paint.
  3. On the normal page, call takeSave. applySave runs inside that call, before the paint. A continued file keeps the seed and the speed from the file.
  4. On the normal page only, if takeSave did not continue, roll the seed now. A missing key, a file that will not parse, and a version other than 1 all take this step. The test path does not. A test page never continues a file, and that fact must not roll over seed 11.
  5. Then call renderChrome at line 5746. The intro lines come after that paint.

?test still returns before takeSave, as the block at line 5741 does now. The test edge stops at seed 11. On the normal page, a missing key, a file that will not parse, and a version other than 1 roll a seed and start empty. A file that will not parse, and a version other than 1, stay on disk until that new game writes. A continued file does not roll.

Defect order

The three shorts stay the constants at lines 679 to 681. Structure is 60. Fuel lines are 0 seconds. Thrust is 1400 kN. A healthy article is still Structure 100, Fuel lines 40 seconds, and Raptor 1 at 1814 kN. The proof floor stays 70. The fuel-line floor stays 5 seconds. The engine floor stays 1500 kN.

The seed picks which short comes first. It does not pick a new number. Six orders sit in a fixed list. Index 0 is the order the game uses today.

const DEFECT_ORDERS = [
  ["stage", "fitting", "engine"],
  ["stage", "engine", "fitting"],
  ["fitting", "stage", "engine"],
  ["fitting", "engine", "stage"],
  ["engine", "stage", "fitting"],
  ["engine", "fitting", "stage"],
];

A numeric seed uses DEFECT_ORDERS[roll(seed, 1) % 6]. Salt 1 belongs to the defect roll only. A null seed does not call roll. It uses index 0.

function mix32(n) {
  n = n >>> 0;
  n = Math.imul(n ^ (n >>> 16), 0x7feb352d);
  n = Math.imul(n ^ (n >>> 15), 0x846ca68b);
  return (n ^ (n >>> 16)) >>> 0;
}
function roll(seed, salt) {
  return mix32((seed >>> 0) + Math.imul(salt >>> 0, 0x9e3779b9));
}

The mix is fixed for this row. A later row that changes it needs a new save version. Until then, the same seed always yields the same order and the same sky.

applyNewArticle at line 1494 still adds 1 to builtArticles, then takes index (builtArticles - 1) % 3. defectRestored still returns before writing the short. A restored part still leaves that later article healthy. Load does not call applyNewArticle. Vehicles already in the file keep stageLife, fittingLifeS, and thrustKn.

A null seed keeps that contract for the old file. Articles already built stay as they are. The next article follows stage, then fitting, then engine, from the saved count. The sky stays the old table too. spanDays at line 1103 stays Math.random. The span is stored on the job when the player presses the button.

The sky

weatherOn at line 1822 still returns one row for the day. The row is still { sky, wind, storm }. renderWeather at line 3857 still writes the header as sky, wind, and "kn". The lamp still uses rangeShut at line 1897. A storm closes the range. Wind over the pad limit closes it. Level 1 limits wind at 20 kn. Level 2 limits wind at 28 kn.

The seeded table reorders the days the player already has. It does not invent a wind. The kind list starts as today's sequence. The wind queues start as today's numbers, in today's order. The first Clear gets 8, then 12, 10, 6, and 14. Wind gets 24, then 22, then 26. Storm gets 36, then 32. A Storm row has storm: true. The other rows have storm: false.

Five days are Clear, and all five are open at level 1. Three days are Wind, and all three are closed at level 1 and open at level 2. Two days are Storm, and both close the range at either level. The seed changes the order only.

function shuffle(list, seed, salt0) {
  const a = list.slice();
  for (let i = a.length - 1; i > 0; i--) {
    const j = roll(seed, salt0 + i) % (i + 1);
    const tmp = a[i];
    a[i] = a[j];
    a[j] = tmp;
  }
  return a;
}

Weather calls shuffle with salt0 10. The salts used are 19 down to 11. They do not overlap salt 1. The kind list before the shuffle is Clear, Clear, Wind, Clear, Storm, Wind, Clear, Clear, Wind, Storm.

The table is not stored. weatherOn derives it from the seed. G may cache the 10 rows after the first read. Load clears that cache and derives again. lockSky still wins, at the existing check on line 1823. The lock is not saved. It exists only on a test page. A null seed does not shuffle. weatherOn returns the literal table already in the file. The cycle still repeats with (day - 1) % 10, as line 1836 does now.

Speed

The day clock is the wait. Line 5631 adds real milliseconds to dayAcc. The while on line 5632 calls dayTick each time the accumulator reaches the day length. Builds, refurbs, the cryo proof, the tanking run, and the data review all wait on dayTick.

2x and 4x change that threshold only. The day length becomes MS_PER_DAY / speed. They do not multiply dt passed to updateRollout. A rollout, a raise, a lower, a fill, a fire, and a flight keep the clocks they have.

A speed change keeps the fraction of the current day. If the day is half gone at 1x, it stays half gone at 4x. The change does not call dayTick by itself. A missing or unknown speed loads as 1. The legal values are 1, 2, and 4. Speed is saved. A reload otherwise snaps the header back to 1x.

applySave reads speed before it clamps dayAcc. The clamp at line 5467 becomes the loaded day length, not always MS_PER_DAY. A 0.14.1 file has no speed field, so it loads at 1x and the old clamp still fits.

wikiTime at line 3206 reads MS_PER_DAY and states one day length. It must divide by the current speed. That string includes MS_PER_DAY and does not include speed. Put G.speed in that signature so the time page rebuilds when the speed changes. The test intro log becomes "A day here lasts half a second at 1x." It also names seed 11.

Skip

The header button label is Skip. The function is skipToEvent. It is not skipEvent at line 2426. That older function only finishes a fire picture. Escape during a fire still calls it, at line 5249. The header Skip does not call it.

Skip refuses, and does not move the day, in this order.

  1. The day is paused. The log says "The day is paused."
  2. A fill is on the clock. The log says "The tanks are still loading."
  3. A fire is on the clock. The log says "The static fire is still burning."
  4. A flight is on the clock. The log says "The rocket is still in flight."

fluidsMoving at line 1185 is the same three kinds. The refuse checks them by kind so the log can name the right one. A road roll, a raise, and a lower do not refuse. Skip does not cancel them and does not wait for them.

If none of those block, Skip counts days without applying them. The count uses copies of factoryJob.daysLeft, each vehicle's testLeft, inspectLeft, and refurbLeft, and weatherOn for the future day. The cap is 16 days. A build is at most 12 days. Five of the 10 days are closed at level 1. Today is one of them, so at most 4 closed days follow, and the next open day is at most 5 days later. The cap is the backstop when a test lock paints every day as a storm.

A day counts as the landing when any of these becomes true after that day tick.

  • A factory job was present and its copied daysLeft has reached 0 or less. That covers the rocket build, Raise Raptor thrust, and the hidden dry-mass job. All three finish in finishFactoryJob.
  • A refurb was counting and its copied refurbLeft reaches 0. Engine, Fuel lines, and Structure all count.
  • A cryo proof or a tanking run was counting and its copied testLeft reaches 0.
  • A data review was counting, with status inspect and inspectLeft above 0, and the copy reaches 0. The rocket becomes ready on that day. Skip does not start a proof, a tanking run, or a fire.
  • The range was closed at the moment of the press, and the future day is open at the pad limit from that same moment. If the range was already open, an open day is not a landing.

The copied counters follow dayTick at line 1406. A job decrements even when daysLeft is already 0, and then it finishes. A refurb, a proof, a tanking run, and a review decrement only when the remaining count is above 0. Weather is read after the day increments. Two landings on the same day both finish. Skip does not stop inside one dayTick.

If the count is 0, the day does not move and dayAcc stays as it was. The log says "Nothing to skip to." A refusal does not zero dayAcc either. If the count is N, set G.dayAcc to 0 before the first dayTick. Then call dayTick N times. Leave that zero in Skip. Do not put it inside dayTick.

dayTick at line 1406 never reads or writes dayAcc. The frame at lines 5631 to 5632 adds real milliseconds, subtracts one day length, and then calls dayTick. What remains after that subtraction is the start of the new day. A zero inside dayTick would wipe that remainder. Skip calls dayTick outside that while, so the zero stays 0 through all N ticks.

Each tick still resolves the real jobs, pays a goal if a finish earns one, and autosaves. The "N days left" lines at lines 1412 to 1414 stay quiet during those ticks. Finish lines still log. dayTick writes the save at line 1436, and savePayload stores dayAcc at line 5363. The zero has to be in place before that write. With the zero first, the last tick's save holds the landing day and dayAcc 0. No second write is required. After the ticks, the log says "Skipped to day D." Newest line first, as log already unshifts.

That file lasts only until the next dayTick that is allowed to write. The next frame adds a few milliseconds and does not cross the day length, so an idle reload on the landing day still reads dayAcc 0 through pagehide. The next natural tick saves the new day and the remainder the while left. That remainder is not the skip's 0.

A reload during a fill, a fire, or a flight reads the last file a tick was allowed to write. autosave and pagehide both return when fluidsMoving() is true. The reload returns the landing day with dayAcc 0 only when that motion started on the landing day, before the next boundary. The rocket has to be able to load already. It is on the mount, the cryo proof and the tanking run are settled, and the tanks hold a fire load, so Static fire calls startFill at line 2217. FILL_SEC is 2 seconds. A day at 1x is 4 seconds. Start that load before the boundary.

A build finish does not leave a rocket that can load. finishFactoryJob sets at_factory at line 1548. The rocket still rolls to the bay, rolls to the pad, and rises. Each road is 2 to 14 seconds, at lines 741 and 742. The raise is 2 seconds, at line 616. Those motions are not a fill, a fire, or a flight, so each day boundary writes. The build-finish day is already gone before a load can start.

On ?test, autosave returns at once and does not write starbase-save. The in-memory zero still holds for the next frame. Worked check, seed 11, pad level 1, day 2, no job and no test running. Skip sets dayAcc to 0, then runs two day ticks. The save from the second tick stores day 4 and dayAcc 0. The header reads day 4, Clear 12 kn, and Range open. The next dayTick that is allowed to write replaces that file.

The save

The key stays starbase-save. The test key stays starbase-save-test. Version stays 1. takeSave at line 5520 still rejects any other version, leaves the file in place, and logs "This save is from another version." A file that does not parse still logs "The save could not be read." and still is not deleted. The game does not delete a file it does not understand. Nothing is sent to a server.

seed may now be a whole number. speed is new. The next write sets label to 0.14.2-seed. The label is how a person sees which build wrote the file. Version stays 1 either way. Speed writes 1, 2, or 4.

  seed: 11,

The rest of savePayload at line 5355 stays. The game still does not save the camera, the open sheet, the drag, the dormant kerosene stock, or skyLock. It still saves paused, dayAcc, the fleet, the factory job, and road, raise, and lower motions. It still waits to save while a fill, a fire, or a flight is running. No weather array is added. No defect-order array is added. Both are functions of seed, or of null. builtArticles and defectRestored stay the record of which shorts have already happened.

A 0.14.1 file looks like this and must continue.

{ version: 1, label: "0.14.1-teeth", seed: null }

A field that is missing, null, or not a whole number in range does not reject the yard. Missing or null is the 0.14.1 file. The old order and the old sky stay, and the game does not log a seed error. A present but unusable seed logs "This save has no usable seed. The old sky stays." and then follows the same old rules. The next autosave writes seed: null again for that file. It does not invent a seed under a yard the player already built.

On load, speed is applied before dayAcc is clamped to MS_PER_DAY / speed. Vehicles are copied as applySave already copies them at line 5416. Their part numbers are not run through the seed. An old page can open a new file, because version stays 1, and then ignore the seed. That downgrade is not a supported path. The supported path is the new page opening the old file.

Test hooks

window.__sb exists only when the URL has test, as the block at line 5650 does now. Keep every hook that is already there, including saveNow, loadSave, lockSky, snap, and restartGame.

  • setSpeed(n) sets 1, 2, or 4, with the same fraction rule as the header. Any other n sets 1. It does not write starbase-save.
  • skipToEvent() runs the header Skip. It returns how many days the clock moved. A refusal returns 0.
  • setDay(n) sets G.day to a whole number of at least 1, sets G.dayAcc to 0, and redraws. It does not call dayTick. It does not finish a job. It does not pause the day. Pause would make the next Skip refuse. On ?test the day length is 500 ms, so a later turn can still leave the day. Read snap in the same turn.

snap keeps its current fields. seed stops being hard-coded null at line 5696. It reports G.seed. Add speed, dayAcc, defectOrder, and sky. defectOrder is the three part names. sky is the object { sky, wind, storm }. It is not the header string. saved still means the real key starbase-save exists. A test page must still leave that flag false unless a real game wrote it earlier.

A test start reports this shape.

seed: 11,
speed: 1,
defectOrder: ["stage", "fitting", "engine"],
sky: { sky: "Clear", wind: 8, storm: false },
dayAcc: 0

The header string Clear 8 kn is a separate check. Opening the test page does not call saveNow or loadSave. saveNow still writes only starbase-save-test. loadSave still reads only that key. A loaded test file with seed: null uses the old sky inside the test yard. That is how a check can rehearse the migration without the real key. lockSky still overrides the table for one check.

There is no metrics stack. The log and the test snap are the record. A new game, including a test start, logs "This game uses seed N." A continued game does not. A skip that moves logs "Skipped to day D." plus the finish lines dayTick already writes. A speed press does not log. The pressed header button is the record.

Out of scope

  • The Starhopper rename, the serials SH-1 and SH-2, or a loaded TA serial rewrite. Those wait for the 0.15.0-hop design. The hop cell already holds that paragraph. This row does not apply it.
  • The hopper shape, the hop, repeat hops, the heights 25 m, 50 m, and 150 m, the countdown, or the flame.
  • Bay money prices, a new currency, or a fail roll. The engine stays 24 steel and 2 days, or 1 day at pad level 2. Fuel lines stay 1 day and no steel. Structure stays 4 to 5 days and no steel. The button shows that span before the press. The refurb goal stays 40. Those are startPartRefurb at line 3896, engineRefurbDays at line 1269, partJobLine at line 3922, and GOAL_PAY.refurb at line 637.
  • Sound, the pipeline, the cadence count, and the high hop. 0.16.0-high-hop stays the high hop only. 1.2.0-refurb stays the flown-stage check.
  • Slots, flight history, or a harder start. Those stay on 8.4.0-saves.
  • A new wind number, a new sky word, or a hidden miss chance.
  • Seeding the build-day roll, the upgrade-day roll, or the structure-day roll.
  • Renaming REFURB_FAIL_MIN and REFURB_FAIL_MAX. The names are old. The button is not a fail roll.
  • Revealing an untested part. The sheet still says "not tested" until a test reads that part.
  • A second save key, a version bump, or a stored weather table. Version stays 1. seed: null keeps the old order and the old sky.
  • Speeding the road, the fill, the fire, or the flight. Speed divides the day length only.
  • Editing index.html in the design session. Code starts only after 0.14.1-teeth has shipped and Tiago has approved that ship.
